# Информационная система «Больница» (Hospital System)
## Лабораторная работа: 4-уровневая архитектура приложения

Проект моделирует работу больницы (стационара) в строгом соответствии с заданием и методическим примером:
1. **Business Layer (`BusinessObjects`)** — сущности предметной области и правила валидации.
2. **Data Access Layer (`DataObjects`)** — доступ к данным (паттерн DAO, Singleton `Db`).
3. **Service Layer (`ServiceLayer`)** — координация бизнес-логики (паттерн Façade).
4. **Presentation Layer (`HospitalApp`)** — графический интерфейс Windows Forms.

---

## 1. Схема предметной области (как всё работает)
- **Госпитализация:**
  - Дежурный врач приемного покоя осматривает поступившего пациента (жалобы, диагноз).
  - Создается **ЭМК (Электронная медицинская карта)**.
  - Пациент направляется в отделение (Кардиологическое, Хирургическое, Неврологическое).
  - В отделении за пациентом закрепляется **лечащий врач**.
- **Назначения врача:**
  - Лечащий врач назначает лечение в ЭМК:
    - *Медикаментозные (таблетки, инъекции)*: дозировка, количество дней, количество инъекций.
    - *Диагностические*: анализ крови, УЗИ, КТ, ФГДС и др.
    - *Профилактические*: массаж, ЛФК и др.
- **Выполнение назначений (Регламент ролей):**
  - **Медикаментозные назначения выполняет только МЕДСЕСТРА**.
  - **Диагностические и профилактические — только ВРАЧИ**.
  - Записи о выполнении фиксируются в ЭМК пациента.
- **Выписка:**
  - Пациент выписывается, формируется официальный **Выписной эпикриз** со списком выполненных назначений и сохраняется в `.txt`.
